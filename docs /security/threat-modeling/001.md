# Threat Model - GET /api/v1/products/{id}

## 1. Descripción del Endpoint
- **Método:** GET  
- **Ruta:** /api/v1/products/{id}  
- **Función:** Recupera información detallada de un producto específico por su identificador único.  
- **Datos devueltos:** JSON con campos como `name`, `description`, `price`, `stock`.

---

## 2. Supuestos
- El endpoint requiere autenticación mediante token JWT.
- El parámetro `{id}` es un UUID válido.
- El servidor aplica validación de entrada.
- El acceso está limitado a usuarios autorizados.

---

## 3. Activos a Proteger
- Información confidencial del producto (precios internos, datos de proveedores).
- Integridad de la base de datos.
- Disponibilidad del servicio.

---

## 4. Posibles Amenazas (STRIDE)
| Categoría | Descripción | Ejemplo | Mitigación |
|-----------|-------------|---------|------------|
| **Spoofing** | Suplantación de identidad de usuario | Uso de tokens robados | Validar JWT y revocar tokens comprometidos |
| **Tampering** | Manipulación de parámetros `{id}` | Cambiar `{id}` para acceder a productos no autorizados | Validación estricta y control de acceso por roles |
| **Repudiation** | Negación de acciones | Usuario niega haber solicitado datos | Logging con trazabilidad y auditoría |
| **Information Disclosure** | Filtración de datos sensibles | Exposición de campos internos | Filtrar campos y aplicar control de acceso |
| **Denial of Service** | Sobrecarga del endpoint | Envío masivo de requests | Rate limiting y detección de patrones anómalos |
| **Elevation of Privilege** | Acceso a datos restringidos | Usuario básico accede a productos premium | Verificación de permisos en cada request |

---

## 5. Controles de Seguridad Propuestos
- Autenticación robusta (JWT + expiración corta).
- Validación de parámetros `{id}` (formato UUID).
- Filtrado de campos sensibles en la respuesta.
- Rate limiting (ej. 100 requests/min por usuario).
- Logging y monitoreo de accesos.
- Auditoría periódica del endpoint.

---

## 6. Riesgo Residual
Tras aplicar las mitigaciones, el riesgo residual se considera **bajo**, pero requiere monitoreo continuo y pruebas de penetración trimestrales.

---

## 7. Notas
Este modelo debe revisarse si:
- Cambia la estructura de datos del producto.
- Se modifica el mecanismo de autenticación.
- Se amplía el acceso a nuevos roles de usuario.
